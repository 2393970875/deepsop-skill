## 强制执行顺序

```
步骤1: 第1波 WebFetch（12次，一次性全部发起）
步骤2: 第2波 Browser  + 第3波 WebSearch（可并行）
步骤3: 合并所有搜索结果到 ${searchResults}
步骤4: 开始 AI 推理各阶段（1/2/3/4）
```

**不允许**：先推理再搜索、搜索不完整就降级虚拟、跳过部分平台。

---

## 并行搜索策略（v5.1）

### 阶段0：全平台搜索

| 波次 | 子组 | 工具 | 搜索次数 | 并行方式 |
|------|------|------|---------|----------|
| 第1波 | 全部平台 | WebFetch | 12次 | **同时发起，不设间隔** |
| 第2波 | 抖音+视频号+快手 | Browser | 3-4次 | 逐一执行，每次≤30s |
| 第3波 | 通用搜索 | WebSearch | 2次 | 可用时与第2波并行 |

### 后续阶段

阶段1/2/3/4 不再搜索，直接基于阶段0的 `${searchResults}` 进行推理。
如果阶段0数据严重不足（所有平台都未采到），AI 自行发起1-2次补充搜索。

## 结果合并与注入

所有搜索工具的结果合并为统一格式：

```json
[
  {"source": "WebFetch", "platform": "百度", "status": "hit|miss|blocked", "items": [...]},
  {"source": "Browser",  "platform": "抖音", "status": "hit|miss|blocked", "items": [...]},
  {"source": "WebSearch", "status": "hit|skip", "items": [...]}
]
```

**status 字段说明：**
- `hit` — 成功获取到数据
- `miss` — 正常请求但无相关内容
- `blocked` — 反爬/登录拦截
- `skip` — 工具不可用

## 速率控制

| 波次 | 策略 |
|------|------|
| 第1波 WebFetch | **零间隔，全部同时发起** |
| 第2波 Browser | 逐一执行，每次≤30s |
| 第3波 WebSearch | 与第2波并行 |

---

## 重试与容错

| 异常 | 处理 |
|------|------|
| WebFetch 反爬/403 | 记录 blocked，换 Browser 备用方案 |
| Browser 超时 | 记录 blocked，跳过该平台 |
| WebSearch 不可用 | 跳过，不影响 |
| 所有搜索均不可用 | 降级纯虚拟（标注⚠️全部虚拟） |
